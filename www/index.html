3 Machine

Machine options

The published pin comes from the provider’s hypervisor scan, rather than attestation. It trusts the provider and whoever can answer the machine address inside its network at scan time.

Use a dedicated, already confirmed provider account. This PoC uses an operator-supplied account rather than seed-based vendor recovery. It supports one outstanding purchase per store, external payment of the initial period, and published Ed25519 host keys. No stock or connectivity is promised.

Provider key unset.

App Lock, reload and worker loss clear the provider key. Re-enter the same account to resume the saved purchase.

New machine

Registering the machine SSH public key with the provider does not enroll the relay. Before configuration, copy the separate relay public key and ask your relay operator to enroll it. You still need published pins and approvals for the goal, class, access and installation declaration.

Will this machine serve people you have never met? If unsure, choose Not sure.

Existing machine

This PoC supports one existing machine per fresh local store. Each machine name permanently binds these connection fields, pin, profile and elevation. To change them, use a fresh local store and a new name; keep the current store for its task history. Obtain the host fingerprint independently; a presented SSH key is never accepted here.

Will this machine serve people you have never met, for example by renting out space on it or hosting other people's accounts?

If unsure, choose Not sure. That class never holds spendable keys and binds alone.

4 Task

Task options

After enrollment, configure inference, then press Start session for the displayed model and machine. Copy its public keys. Install the SSH line and enroll the separate relay public key with the relay operator.

Set the session’s goal. Accept it with commands that check the result. Edit and propose the installation declaration, then approve its requirements card. Press Resume to continue. Commands require that approval.
